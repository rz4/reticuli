# Revision v2.4: the kernel adopts format 3, and the cost band becomes declared-only

The kernel claim moved on 2026-09-18, `82a81357…` → `fac55f89…`. Two
changes, both foreseen and both ratified in prior discussion, batched into
one revision so a single re-proof settles them together.

## What moved into the boundary

**Format 3.** The kernel recipe now declares `format = 3`, and its produce
steps spell their producer guidance `guidance` instead of `request`. At
format 3 that guidance is stripped from the root preimage: a hint helps a
producer find an implementation but cannot decide whether one is accepted,
so rewording it must not rename the claim. The suite pins this directly —
two format-3 claims differing only in guidance wording share one root, both
key spellings strip identically, and a format-1 pair with different request
text keeps different roots, because past formats hash the whole recipe
forever. This is the principle from the boundary manifesto reaching the
kernel's own identity, not just the repository's.

**The cost band is hard only when declared.** Before this revision the
three-machine cost band rejected an out-of-band M1/M3 ratio at the default
tolerance whether or not the claim declared one. That contradicted the
ratified rule that only declared conditions are hard, and it had a
concrete witness: the first real end-to-end three-machine proof (a user's
`primes` claim, gpt-5 as M3) was rejected on "cost band" for exhibiting the
ordinary discovery-versus-rebuild gap. Now a tolerance written into the
recipe is inside the root and gates the test like any pinned condition,
while an undeclared band is computed, reported, and left for a reader to
weigh — an observation, never a verdict. The suite pins both directions.

## What did not move, and what it costs

The five layers above the kernel held: their criteria did not change. The
chain's kernel layer now reproduces `fac55f89…` because `pack` learned a
format-3 path (`_produce_step` emits `guidance`, the recipe declares the
format), and `scripts/selfclaim.py` builds the kernel layer at format 3 to
match the sealed claim.

**The proof stays open.** v2.3 was sealed with no proof; v2.4 inherits that
honestly — a revision never carries a predecessor's proof across a moved
root. Re-earning it against this stronger suite is the paid rebuild, and it
now yields two answers for one spend: a guided M3 and, because guidance is
outside the format-3 root, a `--without-guidance` M3 that must land the same
root from the criteria alone.

## Held, still, for a later deliberate pass

The examples remain at formats 1 and 2 (migrating them is churn without
new evidence). The promise's own context digest, the `mint/` → `sign/`
directory rename, and recording the producer's scaffold alongside its model
are all deferred. This revision is deliberately minimal: the two changes the
whole-repository rebuild actually needs under it, and nothing more.
