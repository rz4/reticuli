## The seam

`pack` accepts PATTERNS in both `generated` and `inputs`. The r10
kernel expands only `generated`, so `selfclaim`'s
`inputs=["checks/*.py"]` reaches the recipe as a declared input named
literally `checks/*.py`, and `seal` cannot hash it. Reproduced three
ways (the judge's substituted gate at 21 s, a hand-built workspace,
the true materialized audit room).

`authoring_check` passes a pattern for `generated` and a literal
filename for `inputs` in every fixture — one side of a symmetric
parameter pair exercised, the other side free. A conforming
implementation implemented exactly the exercised half. Staged:
`research/proposals/pin-glob-expansion-in-inputs.md`.

## The era caveat, measured

closed every seam a codex prior exposed, reaching zero new seams at
r9. A different prior, on first contact, found one load-bearing seam
and one unpinned word — in places codex never touched, because codex's

number rather than a worry: **one load-bearing seam in twenty layers,
with the foreign tree still able to perform the entire job.** Far
better than "complete only for its own prior" would predict; plainly
not "complete".

## A correction, recorded

An earlier diagnosis in this session reported the r10 tree refusing a
format-4 claim with `core.FORMAT == 3`. That was a measurement error:
the diagnostic script's tree path was stale and still pointed at the
r7 lineage, which legitimately predates format 4. The r10 tree is
format 4 throughout and passes `core_check`. The error is recorded
because an instrument that can be misaimed is a fact about the
instruments, and the register keeps those.
