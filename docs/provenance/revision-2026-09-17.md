# Revision v2.3: the kernel claim moves toward the acceptance boundary

The kernel claim was revised on 2026-09-17, and this one is different in
kind from v2.1 and v2.2. Those pinned behaviors a rebuild had gotten wrong.
This one also acts on a principle stated plainly by the keyholder:

> A byte belongs to the identity of a claim if and only if changing that
> byte can change whether some realization is accepted. Everything else is
> shell, evidence, guidance, or residue.

v2.3 is the first step of aligning the tool with that rule. It does not yet
remove producer guidance from the root — that is a format change (format 3),
and it needs the keyholder's sign-off before it seals, because it changes
what a root *means*. What v2.3 does is the part that fits inside the current
format.

## What the suite now pins

**The recipe's two names (finding 13, in the kernel's own suite).** Twins
built under `claim.toml` and `reticuli.toml` with identical content must
share one root — the filename is outside the preimage — and a conformant
kernel must read both. The witness was concrete: the v2.2 blind rebuild
produced a kernel that satisfied the kernel claim while being unable to
read the canonical `reticuli.toml`, so it could not read the very claim it
satisfied. v2.2 pinned this only at the repository-level vectors; v2.3 puts
it where it belongs, in the acceptance suite that defines what a kernel is.

**The three-valued verdict.** The crosscheck now returns `accept`,
`reject`, or `incomplete`. A hard condition must be true to accept and
rejects on false; a hard condition the claim *declared* but the run did not
measure yields `incomplete`, which can never accept, because unknown
evidence is not evidence. This corrects a two-day-old defect of ours: a
declared cost ceiling with no measurement used to pass. It does not. An
observation — producer independence, a cost band with no shared unit —
still never decides; only declared conditions are hard.

**The declared cost ceiling as a hard condition.** The kernel claim now
declares `envelope = { usd = 40.0 }`, set from this claim's own ledger
history ($3.40 first-try on v2.1, $25.74 resumed on v2.2) with honest
headroom. A rebuild measured over the ceiling is rejected; a proof that
never measured dollars is incomplete.

**The declared environment**, carried from the v2.3 work already in the
tree: `[claim] environment` is a pinned input, the room is furnished from
its hash-named artifacts before judging, and an unfurnishable room is an
environment failure.

## What is deliberately still open

The producer-guidance-out-of-the-root change (format 3), the repository
root/promise split, and the guidance-blind rebuild mode are designed and
agreed but not yet built, because each changes what a root means and the
acceptance of that change is the keyholder's act, not the tool's. This file
is the witness ledger's newest entry; the next entries will cite the
counterexamples that format 3 is meant to exclude.
