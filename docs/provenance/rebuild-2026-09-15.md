# The blind rebuild of the kernel

Bootstrap step 3 (`bootstrap.md`): the v2 kernel was regrown blind from the
seed claim. This file is the run's record.

## Setup

- **Room**: an isolated directory containing exactly two files — `claim.toml`
  and `checks/kernel_check.py` (1,132 lines). No kernel source, no spec
  documents, no v1 code.
- **Producer**: `claude-opus-5`, maximum reasoning effort, a fresh agent with
  no conversation context (not a fork — the orchestrating session had read
  the v1 kernel, so a context-inheriting agent would not have been blind).
- **Confinement**: instructed, not jailed — the producer was directed to
  read nothing outside the room and reported compliance (given-file mtimes
  unchanged; only `reticuli/` written). Recorded as a caveat, not proof.
- **Independence: unestablished.** Same vendor as the v1 lineage. A
  cross-vendor rebuild remains open.

## Result

- **Pass.** `python3 checks/kernel_check.py` exits 0 and writes `KERNEL_OK` —
  re-earned independently by the orchestrating session after the run, from a
  deleted-verdict state, and again inside `conformance/kernel/`.
- **Kernel**: `reticuli/kernel.py` 1,451 lines (55 top-level defs, stdlib
  only) + `reticuli/__init__.py` 13 lines. v1's kernel is ~900 lines — a
  byte-different member of the same equivalence class.
- **Root agreement**: `conformance/reference_seal.py` and the regrown kernel's own
  `root()` compute the identical root for the seed claim —
  `d64cc301082f420f4541150618d8774c0ea6c1fc7015b15ce7fd001343ccb405` —
  two implementations of `spec/identity.md` written by different hands (and
  the producer hit all 12 golden serialization vectors on its first probe).
- **Seal**: performed by the regrown kernel itself (`kernel.seal("seed")`);
  verified by both implementations; phase `sealed`.

## Negative controls (the pass is earned, not skipped)

The producer verified the conditional test paths actually engage on this
host: corrupting the signature namespace fails the signing assertion
(line 779); unseeding the mutant sampler fails determinism (line 1096),
reproducibly. Both edits reverted; clean pass re-confirmed.

## What the check under-specifies

Free choices the acceptance suite does not pin — where a second independent
rebuild would likely differ (spec-width findings, feed back into `spec/`):

- concrete names of `STORE`/`LEDGER`/`SIGN_DIR` (only their relationships are
  pinned; the producer chose `.reticuli`, `.reticuli/ledger.jsonl`,
  `.reticuli/mint`);
- manifest schema beyond `name`/`root` strings; proof content beyond
  truthy + JSON round-trip;
- the passing gate status string (only mismatch/failed/environment/timeout
  are pinned);
- default gate timeout; cost tolerance anywhere in [1.5, 4.0) conforms
  (producer chose 2.0); which keys `cost()` totals;
- `sandbox()` return shape beyond backend position; whether it writes its
  own ledger line;
- `gate_deciders` heuristic beyond two vectors + three vacuity cases;
- `mutation_score` survivors' element type (only determinism pinned);
- whether `verify()["root"]` reports stored or recomputed when they disagree.

## Hardest parts (producer's account, abridged)

The canonical serializations were exactly specified and landed first try.
The real traps: the sandbox-inheritance contract (`RETICULI_JAILED` must
report backend `inherited`, never the underlying type); killing a timed-out
gate's whole process group (an orphaned child holding the pipe otherwise
defeats the timeout); `seal()` must run no gates and no preflight (re-running
would destroy the forged-verdict fixture's `mismatch`); mutation scoring
valid-and-lethal in both directions at once; `cost()` totaling only the keys
the ledger names; and two distinct confinement boundaries (`realpath` for
symlinks, `st_nlink == 1` for hardlinks) rather than one.
