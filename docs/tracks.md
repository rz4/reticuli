# Tracks

Three reading orders by use case. Each row is a sequence; later tracks
assume earlier ones.

## 1 — Receive or ship software

Re-earn a received claim's verdicts without trusting the sender; publish
work that survives the same procedure.

[Quickstart](quickstart.md) → [the process §1–5](process.md) →
[receiving](receiving.md) → [threat model](threat-model.md); shipping:
[capturing](capturing.md) → [releasing](releasing.md).

## 2 — Reproducibility in agent work

Run agents as producers judged by machinery they cannot influence; probe
model capability before paying for it; review machine-written PRs by
holding the criteria to account.

[Working with agents](agents.md) → [writing criteria](criteria.md) →
[producing](producers.md) → [GitHub and CI](github.md).

## 3 — Reconstruct and improve the specification

Where independent gate-passing implementations disagree, the criteria were
silent; the disagreement measures the silence. Convert silences into
reviewed, signed amendments.

[The process §6](process.md) → [zeta internals](zeta.md) →
[transitions](transitions.md) →
[`crosscheck`](book/reticuli/reticuli._kernel.crosscheck.md),
[`zeta.lib.split`](book/zeta/zeta.lib.split.md),
[`zeta.lib.entry`](book/zeta/zeta.lib.entry.md).

Invariants across all three: provenance before novelty; replay before
belief; signature before force.
