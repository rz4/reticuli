# The kernel claim

Root `e650b524528ff3b821e48099c818f2de24d0da60a70e27dc120752da7f60e2df`.

- `reticuli.toml` — two generated outputs (`reticuli/__init__.py`,
  `reticuli/kernel.py`) and one gate (`checks/kernel_check.py`, verdict
  `KERNEL_OK`).
- `checks/kernel_check.py` — the acceptance suite: the complete executable
  definition of "a correct kernel". It is a pinned input, so its bytes are
  inside the root. Never format it; see `spec/identity.md`.
- `reticuli/` — a conforming implementation. Generated, therefore *outside*
  the root: these bytes can be deleted and regrown, byte-different, and the
  claim keeps its name.

`criteria/kernel_parity.py` holds `src/reticuli/` — the package this
repository ships — to this claim, by having the claim's suite judge the
living bytes.

## Lineage, and what is and is not proven

This claim is the **v2.2** revision. The chain: `d64cc301…` — the proven
birth claim, since retired from this repository with its frozen bytes
preserved outside it — then `4b90feef…` (v2.1), which pinned seven measured
under-specifications and re-earned its own three-machine proof.

v2.2 pins three more behaviors, each measured first: no component of a
declared path may be a symlink and `..` is refused outright (an internal
link can alias generated bytes as pinned ones — found as a divergence
between the kernel and the reference sealer); records (`spec/record.md`)
are the crosscheck's second transport, reader and verdict pinned; and audit
of a claim whose gate is itself a kernel must report completely (finding
12, the v2.1 dissent).

A proof does not transfer across a revision — the v2.1 proof stays with
`4b90feef…` — so this claim's was **re-earned**: a blind `gpt-5` rebuild
against this suite landed on this root with distinct generated bytes, every
verdict re-run, and, for the first time, a full cost ledger on M3 (4.6M
tokens, $25.74, three sessions). Judged satisfied by the living kernel and
by the regrown kernel itself — the latter only over copies whose recipe
carries the legacy name, because nothing in the suite pins the two-name
rule (finding 13, a candidate for the next revision). See
[`../../docs/provenance/revision-2026-09-16.md`](../../docs/provenance/revision-2026-09-16.md)
and
[`../../docs/provenance/crosscheck-v22-2026-09-17.md`](../../docs/provenance/crosscheck-v22-2026-09-17.md).
